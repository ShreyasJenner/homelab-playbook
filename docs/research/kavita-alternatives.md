# Research: alternatives to Kavita

```
Question:   What could replace Kavita for manga, light novels, comics, EPUB and PDF,
            with a good iOS reading path?
Researched: 2026-10-30, from GitHub repos and APIs, official docs, Docker Hub, GHCR
            and the App Store (iTunes lookup API). No host access.
Fits:       Kavita on homelab (Docker, tailnet-only behind Caddy)
```

The current setup is described on the [Kavita service page](../services/kavita.md): manga as CBZ in one folder per series, light novels in a second library, and reading through the Kavita PWA, because Panels needs a paid tier. [Authentik is retired](../services/authentik.md), so there is no identity provider running today. OIDC support counts for little until one comes back. What format the light novels are in (EPUB or CBZ) isn't recorded in the Playbook, so this note covers both.

Repo numbers are from the GitHub API on **2026-10-30**. GitHub's `open_issues_count` includes PRs, so the table shows issues and PRs separately: issues = `open_issues_count` minus the open PRs returned by `search/issues?q=repo:…+type:pr+state:open`. "Last commit" is the newest commit on the default branch. App Store data is from `itunes.apple.com/lookup` on the same day. UI quality is **partly subjective**. It's judged from each project's own docs, screenshots and demo servers, not from hands-on use.

## Summary

1. **Stay on Kavita** unless something specific is missing. It's the only candidate here that handles *every* format in this library, CB7 and image folders included. It has a manga reader with RTL, webtoon and double-page modes, plus EPUB and PDF readers. It's actively developed (v0.9.1.4, 2026-09-02). It already has free iOS paths beyond the PWA: **Komic** (native Kavita API, free to read, Komic+ for progress sync) and **Paperback** (Kavya extension, chapter-level sync). Every alternative below means losing reading progress, because nothing imports it from Kavita.
2. **Komga** is the best switch if the iOS app choice for manga and comics is what matters. It has the largest set of native iOS clients (KMReader, Komic, Yomu, ComicVerse, TritonPanels, Paperback, Panels), RTL and webtoon readers, an EPUB reader, OPDS 1.2 with PSE and OPDS 2 with progress sync, and Kobo and KOReader sync. It has 7 open issues and committed on 2026-10-30. It reads Kavita's one-folder-per-series layout as-is. The catch is that it can't read **CB7**/7z archives, and it has no LDAP.
3. **BookOrbit** fits if a **first-party native iOS app** and one server for ebooks, comics and audiobooks matter more than maturity. It's the official successor to BookLore, with an App Store app (iOS 26+ required), webtoon "long strip", RTL and two-page comic modes, and a "Series folders" scan mode written for the Komga/Kavita layout. The risks: the repo was only created 2026-05-09, it has 532 open issues, it says its API isn't a stable surface for third-party clients, and its migration wizard has no Kavita source.

For **Western comics specifically**, **Codex** is the strongest comics-only server: CB7/CBT, rich ComicInfo/metadata browsing, OPDS 1+2 with PSE and progression, OIDC and Remote-User header SSO. It has no EPUB reader, so it can't hold the light novels on its own.

## Candidates

### Kavita (baseline)

- **Why included:** the current service, kept as the baseline.
- **iOS:** no first-party app. Kavita's FAQ says "Kavita does not yet offer mobile apps", and suggests "Add to Home screen" for the PWA ([FAQ](https://wiki.kavitareader.com/troubleshooting/faq/)). The repo has `UI/Web/src/site.webmanifest` ([repo](https://github.com/Kareadita/Kavita/tree/develop/UI/Web/src)). Kavita's client table lists Chunky and Panels (OPDS + OPDS-PS), Yomu (OPDS, EPUB), and Paperback and Aidoku (API, chapter-level progress sync) ([OPDS](https://wiki.kavitareader.com/guides/features/opds/)). Komic is "a native comic, manga, webtoon, manhwa, and EPUB reader for iPhone and iPad with built-in Kavita support". Reading is free, and Komic+ unlocks offline reading and progress sync ([Komic guide](https://wiki.kavitareader.com/guides/3rdparty/komic/)). Paperback uses the Kavya extension with an API key ([Paperback guide](https://wiki.kavitareader.com/guides/3rdparty/paperback/)). Aidoku installs through TestFlight or sideloading ([Aidoku guide](https://wiki.kavitareader.com/guides/3rdparty/aidoku/)). Panels needs HTTPS for remote access ([Panels guide](https://wiki.kavitareader.com/guides/3rdparty/panels/)). App Store: [Komic](https://apps.apple.com/us/app/komic-comic-manga-reader/id6744676973) (1.35.1, 2026-10-29), [Paperback](https://apps.apple.com/us/app/paperback-comic-manga-reader/id1626613373) (0.8.11, last updated 2025-02-28), [Panels](https://apps.apple.com/us/app/panels-comic-reader/id1236567663) (3.13.9, 2026-10-22), [Yomu](https://apps.apple.com/us/app/yomu-ebook-reader/id562211012) (3.21.0, 2026-10-22), [Chunky](https://apps.apple.com/us/app/chunky-comic-reader/id663567628) (last updated 2020-08-16).
- **UI (subjective):** customizable dashboard and side nav, smart filters, themes, localization ([README](https://github.com/Kareadita/Kavita#what-kavita-provides)). There's a live [demo](https://demo.kavitareader.com/).
- **EPUB/PDF:** the EPUB reader has scroll, 1- and 2-column layouts, vertical writing for Japanese books, in-page progress saving and annotations ([EPUB reader](https://wiki.kavitareader.com/guides/readers/epub/)). The PDF reader "mimics Firefox's pdf reader", with Single, Left-Right and Right-Left layouts ([PDF reader](https://wiki.kavitareader.com/guides/readers/pdf/)). KOReader gets two-way progress sync for archives, PDF and EPUB, and OPDS-PS page streaming ([KOReader guide](https://wiki.kavitareader.com/guides/3rdparty/koreader/)). OPDS and OPDS-PS are on by default ([OPDS](https://wiki.kavitareader.com/guides/features/opds/)). There's no OPDS 2: Stump's docs list Kavita as "Does not support OPDS v2" ([Stump auth docs](https://github.com/stumpapp/stump/blob/main/docs/content/docs/apps/mobile/servers/authentication.mdx)).
- **Maintenance:** v0.9.1.4 on 2026-09-02, last commit 2026-10-28, 147 open issues and 22 PRs. The README still calls it beta "until the 1.0.0 release" ([README](https://github.com/Kareadita/Kavita#notice)). Kavita+ is a paid add-on for metadata, scrobbling and recommendations ([README](https://github.com/Kareadita/Kavita#kavita)).
- **Images:** official `jvmilazz0/kavita` (Docker Hub) and `ghcr.io/kareadita/kavita`, both amd64, arm64 and arm/v7 (registry manifests). The LSIO image is `lscr.io/linuxserver/kavita`, stable releases only, with no armv7. Moving between images only changes the config mount, `/kavita/config` versus `/config` ([LSIO page](https://wiki.kavitareader.com/installation/docker/lsio/)).
- **Auth:** local accounts, plus OIDC since v0.8.8, with account linking by email, auto-provisioning and role sync from the IdP ([OIDC](https://wiki.kavitareader.com/guides/admin-settings/open-id-connect/)). Auth keys (the `x-api-key` header) serve the API, OPDS and third-party apps. "Auth key authentication always remains available" even with password login disabled ([API](https://wiki.kavitareader.com/guides/api/), [3rd party clients](https://wiki.kavitareader.com/guides/user-settings/3rdpartycilents/)). No LDAP or header auth is documented. The FAQ says Kavita can't be used without authentication ([FAQ](https://wiki.kavitareader.com/troubleshooting/faq/)).
- **Comics:** archives "cbr, cbz, zip/rar/rar5, 7zip, raw images" and books "epub, pdf" ([README](https://github.com/Kareadita/Kavita#what-kavita-provides)). There's an Image library type for folders of images ([Images](https://wiki.kavitareader.com/guides/scanner/image/)). The reader does LTR and RTL, vertical pagination, "Infinite Scroll/Webtoon mode", Single, Double and "Double (Manga)" layouts, image splitting and fit by height, width or original ([Comic/Manga reader](https://wiki.kavitareader.com/guides/readers/comic-manga/)). ComicInfo.xml (v2.1 draft) maps to series, volume, chapter, specials and more ([Comics metadata](https://wiki.kavitareader.com/guides/metadata/comics/)). Grouping comes from filenames and metadata, not the folder tree: "Kavita uses filenames and internal metadata for parsing and is not designed to use folder structure" ([FAQ](https://wiki.kavitareader.com/troubleshooting/faq/)). Series must each sit in their own folder under the library root ([Scanner](https://wiki.kavitareader.com/guides/scanner/)). On iOS, Komic covers comics, manga, webtoons and manhwa ([Komic guide](https://wiki.kavitareader.com/guides/3rdparty/komic/)). Whether Panels and Paperback handle RTL and vertical scroll with Kavita is a property of those apps, and Unverified here.

### Komga

- **Why included:** the most established manga/comics server after Kavita, with the widest iOS client support.
- **iOS:** no first-party app. Komga's docs list these native clients:
  - **KMReader** (iOS, macOS and tvOS): "LTR/RTL/vertical/Webtoon reading modes with spreads" plus a native EPUB reader ([guide](https://komga.org/docs/guides/kmreader), [App Store](https://apps.apple.com/us/app/kmreader/id6755198424), free, 7.3, 2026-10-21).
  - **Komic**: progress sync needs Komic+ ([guide](https://komga.org/docs/guides/komic)).
  - **Yomu**: built-in Komga support, "a free manga, webtoon, and manhwa reader" ([guide](https://komga.org/docs/guides/yomu)).
  - **TritonPanels**: a subscription app with no free tier, Komga 1.19+ ([guide](https://komga.org/docs/guides/tritonpanels), [App Store](https://apps.apple.com/us/app/tritonpanels-comic-book-reader/id6782908043)).
  - **ComicVerse**: free; uses OPDS v2 and syncs progress ([guide](https://komga.org/docs/guides/comicverse), [App Store](https://apps.apple.com/us/app/comicverse-cbr-cbz-reader/id6753079682)).
  - **Paperback**: an extension, with a tracker that syncs read chapters ([guide](https://komga.org/docs/guides/paperback)).
  - **Panels**: OPDS "requires either a Panels+ subscription or Panels in-app purchase" ([guide](https://komga.org/docs/guides/panels)).

  Chunky "does not work anymore with Komga 1.4.0+" ([guide](https://komga.org/docs/guides/chunky)). The WebUI ships a `manifest.json` with `"display": "standalone"` ([manifest](https://github.com/gotson/komga/blob/master/komga-webui/public/manifest.json)). How well that works as an iOS PWA is Unverified.
- **UI (subjective):** a mature WebUI. A rewritten "NextUI" went into public beta on 2026-08-10, "running in parallel alongside the existing WebUI", and not all features are there yet ([blog](https://komga.org/blog/nextui-beta)). There's a live [demo](https://demo.komga.org).
- **EPUB/PDF:** in-browser EPUB reader with scroll or paginated layout and custom fonts ([EPUB webreader](https://komga.org/docs/guides/webreader-epub)). PDF is a supported format ([Libraries](https://komga.org/docs/guides/libraries)). OPDS v1.2 includes "OPDS Page Streaming Extension 1.2", and there's an OPDS v2 feed ([OPDS](https://komga.org/docs/guides/opds)). Kobo sync works both ways, with EPUB converted to KEPUB on the fly if Kepubify is present ([Kobo](https://komga.org/docs/guides/kobo)). KOReader sync uses a dedicated API key. EPUB progress syncs at chapter starts only ([KOReader](https://komga.org/docs/guides/koreader)).
- **Maintenance:** 1.29.2 on 2026-10-28, last commit 2026-10-30, 7 open issues and 3 PRs (GitHub API).
- **Images:** `gotson/komga` on Docker Hub and `ghcr.io/gotson/komga` ([Docker](https://komga.org/docs/installation/docker)), amd64, arm64 and arm/v7 (registry manifests). There's no linuxserver.io image (Docker Hub has no `linuxserver/komga`).
- **Auth:** local accounts. "Komga supports social login via OAuth2 and OpenID Connect", matched to users by email, with optional account creation ([OAuth2](https://komga.org/docs/installation/oauth2), [configuration](https://komga.org/docs/installation/configuration)). API keys come from My Account ([KOReader](https://komga.org/docs/guides/koreader)). Stump's docs note that Komga takes them through the `X-API-Key` header ([Stump auth docs](https://github.com/stumpapp/stump/blob/main/docs/content/docs/apps/mobile/servers/authentication.mdx)). No LDAP or header auth is documented.
- **Comics:** archives "cbz, zip, cbr, rar", plus PDF and EPUB. There's an optional library setting, "Automatically convert to CBZ", that rewrites rar/cbr books as cbz in the background ([Libraries](https://komga.org/docs/guides/libraries)). Leave it off for read-only mounts. **7z isn't supported**: "Your files are compressed using 7zip, which is not supported" ([FAQ](https://komga.org/docs/faq)). Image folders aren't listed. The web reader has LTR, RTL, Vertical and "Webtoon: displays all the pages in a continuous vertical strip". It follows the book's reading-direction metadata, fits to screen, width, height or original, and does double pages ([DIVINA webreader](https://komga.org/docs/guides/webreader-divina)). ComicInfo.xml is imported for cbz/cbr ([FAQ](https://komga.org/docs/faq)). "Komga will create a Series for each subfolder of any library, whatever the depth" ([Scan/analysis](https://komga.org/docs/guides/scan-analysis-refresh)), so it's series → books, with no separate volume and chapter levels.

### BookOrbit

- **Why included:** BookLore's README names it "BookLore's official successor and the home of active development" ([BookLore README](https://github.com/booklore-app/booklore#readme)). It's the only candidate with a released first-party iOS app.
- **iOS:** [BookOrbit: The Official App](https://apps.apple.com/us/app/bookorbit-the-official-app/id6811807346) (free, 1.7.0, 2026-10-28) reads "ebooks, PDFs, and comics", with offline reading. It "Requires BookOrbit v3.0.0 or later and iOS 26 or later" ([README](https://github.com/bookorbit/bookorbit#bookorbit-for-iphone-and-apple-watch)). Third-party apps use OPDS. The README warns that the API "is not currently a stable public integration surface" for third-party clients ([README](https://github.com/bookorbit/bookorbit#readme)). The repo has `client/pwa-assets.config.ts` ([repo](https://github.com/bookorbit/bookorbit/tree/main/client)).
- **UI (subjective):** a modern dashboard with stats, achievements and smart scopes ([README screenshots](https://github.com/bookorbit/bookorbit#readme)). There's a live demo linked from the README.
- **EPUB/PDF:** web readers for EPUB, KEPUB, MOBI, AZW3, AZW and FB2, and PDF (page or scrolled mode, odd or even spreads) ([Reader](https://bookorbit.app/reader/)). Three-way progress sync between Kobo, KOReader and BookOrbit ([README](https://github.com/bookorbit/bookorbit#readme)). OPDS lives at `/api/v1/opds` and serves OPDS XML ([OPDS](https://bookorbit.app/opds/)). The OPDS version and PSE aren't documented (Unverified).
- **Maintenance:** v3.6.0 on 2026-10-28, last commit 2026-10-30, 532 open issues and 23 PRs. The repo was created 2026-05-09 (GitHub API).
- **Images:** `ghcr.io/bookorbit/bookorbit`, amd64 and arm64 (GHCR manifest). The Quick Start compose has a `data/postgres` directory ([README](https://github.com/bookorbit/bookorbit#quick-start-docker)). No linuxserver.io image.
- **Auth:** local, OIDC ("native support for Authentik, Keycloak, and Authelia"), and magic links ([README](https://github.com/bookorbit/bookorbit#readme), [Users](https://bookorbit.app/users/)). OPDS accounts "are separate from normal BookOrbit login credentials" and need the `opds_access` permission ([OPDS](https://bookorbit.app/opds/)). With an auth proxy in front, the OPDS, KOReader, Kobo and `/api/v3/` paths must skip the proxy login ([Auth proxies](https://bookorbit.app/auth-proxies/)). Whether it can trust a Remote-User header is Unverified. LDAP isn't documented.
- **Comics:** CBZ, CBR and CB7. Paginated, Infinite and "Long strip" modes, single or two-page view, fit to page, width, height or actual size, L-to-R or R-to-L direction, spread alignment and wide-page handling. RTL can be saved per file ([Reader](https://bookorbit.app/reader/)). Library layout: "One folder per series (Komga and Kavita layout)" via the **Series folders** option. It understands `v01`, `c1001` and Japanese, Chinese and Korean markers, and a ComicInfo.xml series name takes precedence. It can write ComicInfo.xml into CBZ and CB7 ([Library file structure](https://bookorbit.app/library-file-structure/), [Creating a library](https://bookorbit.app/creating-a-library/)). Image folders aren't listed. Its own iOS app reads comics; whether it does RTL and long strip there is Unverified.

### Codex

- **Why included:** an actively maintained comics-only server, recommended by the brief as a check.
- **iOS:** no first-party app. OPDS v1 clients: Panels, PocketBooks, KyBook 3 (which "does not seem to support http basic authentication"), and Chunky. OPDS v2 clients: the Stump app and Readest ([README](https://github.com/ajslater/codex#-opds)). The repo has a PWA manifest ([codex/templates/pwa](https://github.com/ajslater/codex/tree/main/codex/templates/pwa)).
- **UI (subjective):** collector-oriented. You can browse publishers, imprints, series and volumes, your folder tree, or story arcs. There's a "multi-sortable metadata table", in-browser tag editing written back to the files, and online tagging ([README](https://github.com/ajslater/codex#-features)). There's a live [demo](https://demo.codex-reader.app/).
- **EPUB/PDF:** reads "CBZ, CBR, CB7, CBT and PDF comics", and **EPUB isn't supported** ([README](https://github.com/ajslater/codex#-features)). OPDS 1.2 with PSE 1.2, and OPDS 2.0 with DiViNa and OPDS Progression 1.0 ([README](https://github.com/ajslater/codex#supported-opds-specifications)).
- **Maintenance:** v2.5.7 on 2026-10-28, last commit 2026-10-28, 4 open issues and 0 PRs.
- **Images:** `ghcr.io/ajslater/codex`, amd64 and arm64. "The `docker.io/ajslater/codex` image is deprecated" ([README](https://github.com/ajslater/codex#readme)).
- **Auth:** local accounts or anonymous browsing, OIDC, and "Remote-User HTTP header SSO for reverse-proxy single sign-on". OIDC users have no local password, so OPDS needs the per-user API token ([README](https://github.com/ajslater/codex#oauth-oidc)).
- **Comics:** fit to screen, width, height or original. Reading directions ltr, rtl, ttb and btt, two-page view ([reader.py](https://github.com/ajslater/codex/blob/main/codex/choices/reader.py)). Top-to-bottom uses a virtual-scroll vertical pager ([pager-vertical.vue](https://github.com/ajslater/codex/blob/main/frontend/src/components/reader/pager/pager-vertical.vue)). Metadata is read through comicbox, ComicInfo.xml included ([README](https://github.com/ajslater/codex#pdf-metadata)). Image folders aren't listed. There's no manga-specific volume or chapter model. Grouping is publisher → series → volume → issue.

### Stump

### Grimmory

- **Why included:** found while checking BookLore. It's actively developed, and its backend is BookLore's codebase (the Java package is still `org.booklore`; see [BookloreApplication.java](https://github.com/grimmory-tools/grimmory/blob/develop/backend/src/main/java/org/booklore/BookloreApplication.java)). BookOrbit's migration wizard lists "Booklore and Grimmory" together ([Migration](https://bookorbit.app/migration/)).

The listed Komga-API apps are all Android or desktop. Whether iOS Komga clients (KMReader, Komic, Yomu, Paperback) work against it is **Unverified**. The repo has `frontend/ngsw-config.json` and `manifest.webmanifest` ([repo](https://github.com/grimmory-tools/grimmory/tree/develop/frontend)).
- **UI (subjective):** the same feature set as BookLore: smart shelves, metadata lookup, BookDrop ([README](https://github.com/grimmory-tools/grimmory#features)).
- **EPUB/PDF:** an ebook reader (EPUB, MOBI, AZW3, FB2) and a PDF reader with page spreads, both with progress sync ([Getting started](https://grimmory.org/docs/getting-started/)). Kobo and KOReader sync ([README](https://github.com/grimmory-tools/grimmory#features)). "Per-page streaming only works through the Komga API (/komga/api/), not the standard OPDS endpoint" ([OPDS](https://grimmory.org/docs/integration/opds/)).

"OPDS uses its own user accounts, separate from your Grimmory login", shared with the Komga API, over HTTP Basic ([OPDS](https://grimmory.org/docs/integration/opds/)).

ComicInfo.xml support is Unverified.

## Migration from Kavita

**No candidate imports anything from Kavita**: not reading progress, users, collections, reading lists or metadata.

- BookOrbit's migration wizard supports Booklore, Grimmory, Audiobookshelf and Calibre-Web Automated only, and "comic metadata" isn't migrated from any source ([Migration](https://bookorbit.app/migration/)).
- The Komga, Codex, Stump, Grimmory and Calibre-Web docs read for this note have no import feature.
- A GitHub repo search on 2026-10-30 (for "kavita komga migrate", "kavita to komga", "kavita migration progress" and similar) found no Kavita-to-X tool. It found the reverse, [morsok/ko2ka](https://github.com/morsok/ko2ka) ("migrate reading progress from Komga to Kavita"), and a Kavita-to-Kavita database helper ([DieselTech/Kavita-Database-Migration](https://github.com/DieselTech/Kavita-Database-Migration)).
- Kavita publishes an OpenAPI spec and takes auth keys ([API](https://wiki.kavitareader.com/guides/api/), [openapi.json](https://raw.githubusercontent.com/Kareadita/Kavita/develop/openapi.json)). A one-off script could read per-user progress from Kavita and write it to Komga's or Codex's API. That is an inference: nobody has published one, and it would need matching books across the two servers.

**The practical path is to re-point the new server at the same folders, read-only, and run it beside Kavita until it's trusted.** Each User then has to re-create their account and mark progress again, or start fresh.

Folder layout. Kavita expects `Library Root/Series Name/Series Name v01.cbz`, with each series in its own folder ([Scanner](https://wiki.kavitareader.com/guides/scanner/), [Manga](https://wiki.kavitareader.com/guides/scanner/manga/)).

| Target | Kavita layout as-is? | Source |
|---|---|---|
| Komga | **Yes.** "a Series for each subfolder of any library", one book per file. Overlapping library roots aren't allowed, so `/manga` and `/lns` stay separate libraries | [Scan](https://komga.org/docs/guides/scan-analysis-refresh), [Libraries](https://komga.org/docs/guides/libraries) |
| BookOrbit | **Yes**, with the "Series folders" option, which matches the layout Komga and Kavita use. "How files become books" can't be changed later | [Library file structure](https://bookorbit.app/library-file-structure/), [Creating a library](https://bookorbit.app/creating-a-library/) |
| Stump | **Yes.** Series-priority makes "a separate series for each folder that directly contains media files"; library paths must not nest | [Libraries](https://github.com/stumpapp/stump/blob/main/docs/content/docs/guides/fundamentals/libraries.mdx) |
| Codex | **Yes.** It groups by metadata and filename, and also offers a folder view | [README](https://github.com/ajslater/codex#-features) |
| Grimmory | Files are read, but series grouping depends on metadata (Unverified for un-tagged files) | [Komga API](https://grimmory.org/docs/integration/komga-api/) |
| Ubooquity | Yes (it shares folders as they are) | [home](https://vaemendis.net/ubooquity/) |
| Calibre-Web / CWA | **No.** Needs a Calibre library; CWA ingest removes the source files | [CW README](https://github.com/janeczku/calibre-web#readme), [CWA README](https://github.com/crocodilestick/Calibre-Web-Automated#readme) |
| Audiobookshelf | **Poor.** One item per folder | [Directory structure](https://audiobookshelf.org/docs/documentation/libraries/book-library/directory-structure) |

One Kavita-specific point to check before switching:

- **iOS needs HTTPS.** Kavita's and Komga's client guides note that iOS apps require HTTPS for remote connections ([Kavita Komic guide](https://wiki.kavitareader.com/guides/3rdparty/komic/), [Komga Komic guide](https://komga.org/docs/guides/komic)). The current `https://manga.example.com` through [Caddy](../services/caddy.md) over the tailnet already meets that. A replacement would want the same.
