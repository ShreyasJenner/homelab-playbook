# A public Mirror with stand-ins, not a sanitized Playbook

The Playbook stays private and keeps every real value: a runbook is only useful if its addresses, names and paths are the ones on the host. What goes public is the **Mirror**, a copy of the Playbook rewritten commit for commit by `/homelab-mirror`. We rejected sanitizing the Playbook itself, because that would cost the detail that makes debugging fast, and starting the Mirror from a single sanitized snapshot, because the point of publishing is the incident-by-incident history.

## Consequences

- **Two lists decide what goes public, and the owner edits both.** The **Hidden list** says what must never be recoverable from the Mirror, by category, with what is published on purpose beside each one. It is private, like the map, the cuts and the forbidden terms. The **Mirror rules** say how a build gets there, and are published (`.claude/skills/homelab-mirror/RULES.md`). The reasons behind each hidden category live in the Hidden list, not here, so this record stays publishable.
- **Some content is left out, not swapped.** Whole paths, and passages inside shared pages, are cut from every commit; a commit left empty is dropped. A list of forbidden terms makes the leak check refuse any trace of them, so leaving something out is enforced by script rather than by a reader's judgement (decided 2026-11-06).
- **Stand-ins are fixed, never random.** The same Playbook and rules always produce the same Mirror, commit hashes included, so each publish only adds commits. A new rule that matches an old commit rewrites history from there, and that push is a `--force-with-lease`.
- **The owner isn't anonymous.** The Mirror is pushed from the owner's own GitHub account, so the name, handle and email are published as they are, and so are the media titles (decided 2026-11-06). What stays hidden is what leads to the hosts or narrows the location: the domain, the tailnet and machine names, addresses, chosen ports, usernames and accounts, other people, devices, the ISP, and anything finer than the time zone.
- **Some routes to a hidden value are accepted.** Certificate-transparency logs are public, so the dates on the Caddy pages and incidents may narrow the domain, and the Funnel ports and dates may narrow the tailnet and machine names. Split DNS would close the first; the owner accepts both instead (decided 2026-11-05).
- **One full audit, then diff reviews.** Before the first push the Mirror gets a full audit: independent readers go through the final tree and the whole history. After that, each publish gets the leak check and a review of only what changed since the last audited build. A full read after every fix never converged, since each read is a new sample and finds something new. Only a broken rule or a finding that recovers a hidden value stops a push; a finding that only weakens a stand-in can wait for a later publish (decided 2026-11-06). The user pushes by hand; the skill never does.
